# 路由策略

一次请求先被解析成一个池：一个供应商开着的密钥和账号，或一个路由组各成员的头。策略只回答「按什么顺序试这些席位」。休息、会话粘性、首字节之前的失败转移由网关做，不放进策略。策略返回的必须是席位下标的一个排列；返回得不合法或自己 panic，就按原来的列出顺序试，请求仍然会发出去。

本页记录策略本身要守住的语义。网关已按
[routing parity](routing-parity.md) 的第 1–5 步接线；仍然开放的是按请求把同一
供应商里更贴合的密钥提前，以及第 6 步的注册插件等。当前行为以
[Gateway](../subsystems/gateway.md) 和
[路由策略模块能力边界](../routing-strategy-capabilities.md) 为准。

源码：

| 做什么 | 哪里 |
| --- | --- |
| 席位和策略接口 | `internal/routes/routes.go` 的 `Seat`、`Strategy`、`Apply` |
| 除速度优先以外的策略 | `internal/routes/strategies.go` |
| 速度优先 | `internal/routes/fastest.go` |
| 平滑加权轮转 | `internal/routes/round.go` |
| 网关填席位、休息、粘性、失败转移 | `internal/gateway/routing.go`、`chain.go`、`seat.go`、`quota.go`、`limits.go` |
| 路由组 | `internal/gateway/group.go` |

默认策略 `smart` 编在核心里，id 是空字符串。本仓库的其余策略仍在
`routes.Builtin.Find` 的固定 switch 中；可关闭的策略注册插件是
[routing parity](routing-parity.md) 第 6 步的开放项，尚未实现。

## 有哪些

| id | 名字 | 选谁先试 |
| --- | --- | --- |
| `""` | Smart | 额度还够的里面，最大窗口重置得最早的 |
| `order` | 按顺序 | 列表里的第一个，直到它不能答 |
| `rotate` | 轮转 | 每个请求往下挪一位，进程内计数，重启归零 |
| `usage` | 最少使用 | 厂商说的已用比例小的优先；没报比例的按最近发送量 |
| `pace` | 用完前的速率 | 每周剩余额度除以距离重置的小时数，大的优先 |
| `weight` | 加权 | 平滑加权轮转，权重至少为 1 |
| `free` | 免费优先 | 这个模型在该席位不花额度或积分的排前面 |
| `fast` | 速度优先 | 最近流式回复更快的优先，偶尔探测没测过的 |
| `cheap` | 最便宜 | 按这次请求的时刻计价，输入加输出更便宜的优先。只用于路由组 |
| `drain` | 用尽再换 | 停在一个席位上直到用尽，然后停在下一个，续上了也不回来 |
| `expiring` | 免费额度快过期 | 免费的按过期时间，付费的再按 Smart。只用于路由组 |

`order`、`drain` 标了 `Exact`：顺序就是策略给的。其它策略对一家供应商的多个
API 密钥按请求做额外前移仍在 `routes.Exact` 里留有接口，但网关尚未调用它；
当前对外层顺序而言，同一供应商的密钥仍按策略给出的相对顺序。

`ByUse`、`ByFree`、`ByPlan`、`BySpeed`、`ByPrice` 是策略向网关要的附加字段。没置位就不要去读模型目录或速度表，那些读取不便宜。

## 设计

策略是纯排序。输入是 `[]Seat`，输出是下标排列。这样失败转移、限流休息、会话粘性对所有策略是同一套：

1. 网关把候选收成席位，填上这个策略声明要的字段。
2. `Apply` 得到顺序。
3. 正在休息的席位移到最后（限流、失败）。额度用尽的休息和普通失败分开：`Spent` 只表示额度或积分没了。
4. 这次对话若还粘在上次应答的席位上，并且那个席位还能答，就改用它。加权轮转要把这一轮的计数从「抽中的那个」改记到「实际用的那个」。
5. 按这个顺序试。回复的第一个内容字节已经交给客户端之后，不再换。换只发生在还没开始下发的时候。
6. 一个席位失败，试顺序里的下一个。满并发或满每分钟请求数时，让给池里已经空闲的下一个，而不是在这个席位的队列里干等。

额度分成三档，`Used` 是 0–100 的已用比例，只统计约束这个模型的窗口：

| 档 | 条件 | 含义 |
| --- | --- | --- |
| 0 | 低于 90，或只有「周」这类长窗口到了 90 | 还能用。长窗口里剩下的额度在重置时作废，不能因为 90% 就留到最后 |
| 1 | 短窗口（限流帽）到了 90 及以上 | 先留给别人 |
| 2 | 到了用尽线（按顺序、用尽再换是 100） | 只有别人都不行才用 |

`First` 的席位（用户指定先花积分）始终当档 0。`Learns` 的账号还不知道剩余，但回复里会带剩余。这种账号要先试一次，否则永远排在已知账号后面，永远学不会。

## Smart

有空的席位按「最大窗口何时重置」排，重置更早的在前。比较截断到小时，差几分钟不换顺序。窗口从大到小放在 `Soon` 里：先比周，同一小时再比里面的 5 小时。没有周的账号就用它自己的 5 小时，因此会排在「周更晚才重置」的账号前面。

`Unreached` 表示从最大的窗口起，有几个窗口剩下的额度已经不可能在重置前用完。这些窗口不参与比较，改比下一个。否则一个月还剩很多、两周后才重置的席位会一直占着，把本周就要作废的额度挤掉。

重置小时相同，再比 `Lapse`：积分何时作废，更早的在前；没填的排在填了的后面。然后才比预付费钱包余额 `Left`。余额只在 `LeftIn` 相同的席位之间比（同一供应商、同一单位）。不同单位互不比较，只在各自已经占住的名次里重排，避免把「点数少」和「另一家的点数多」放在一把尺子上。

档 1 按已用比例从小到大。档 2 里，还能花积分的（`Credits`）在前，然后已用比例小的在前。`Lead` 的席位只要还没到档 2，整组提到最前，组内仍是上面的顺序。

稳定排序：完全一样的席位保持列出顺序，让厂商的 prompt cache 继续打在同一账号上。

## 用尽再换

每个池在内存里记当前停在哪个 `Key` 上。进程重启后忘掉，从列表里第一个还没用尽的开始。

用尽是这三件之一：`Spent`、已知且已用比例到了用尽线、或上次请求被厂商以额度或积分拒绝（`Drained`）。限流和普通失败只是休息，池仍停在这个席位，网关先试别人，下一轮还是它。

下一轮的顺序是从当前席位起到列表末尾，再接列表开头。这样失败转移的方向和「按顺序」一样。当前席位被关掉或删掉时，改停到其后第一个没用尽的。全部用尽就停在原地。

`Drained` 要记在池上。否则这次请求已经失败转移了，但下一轮来的时候额度窗口刚好重置，池又跳回原来那个账号。用户要的是「用尽一个再换下一个，续上了也不把请求要回去」。

## 最少使用和速率

`usage` 不能把 `Used == 0` 当成「最空」。按量计费的密钥、没读到额度的账号，已用比例也是 0。若按 0 排到最前，订阅额度还空着，请求会去烧付费余额。所以先分四段：正在学习的账号、报过比例且还有空的、没报比例的、档 1、档 2。段内再比已用比例，然后钱包余额，然后最近发送量 `Tokens`。

即将作废的积分（`Lapsing` 至少 0.1 个点，且还有空）整段提前，按 `Lapse` 的小时更早的在前。作废的积分不用白不用，但不值得为了零头打乱整个池。

`Tokens` 是本进程里按约 1 小时半衰期衰减的发送量。没衰减的话，一个上午用得多的账号会把全天的「最少使用」都让出去。

`pace` 的数是「每周还剩的比例，除以距离该周重置的小时数」。未知账号按一整周算（`FreshPace = 100 / (7*24)`），否则它没有速率，永远排不进来。普通 API 密钥没有周，速率是 0，除非这把密钥自己报窗口。

速率只在档 0、且不是正在学习的席位之间分带：先按速率从高到低排，比上一档最高值低过一成（`< 0.9 * top`）才新开一档。同一档里再比钱包、再比 `Tokens`。不能写成「两两相差一成就算同一档」，三个席位各差十二分之一会绕成环，排序不稳定。分带必须先按绝对值排好再画。

档 1、档 2 不参与分带。若让一个 90% 的席位当一档的顶点，会把两个其实一样快的席位拆开。

## 速度优先

每个席位、每个模型记两个衰减平均值，半衰期约 20 分钟，超过约一小时没答过就当没测过：首 token 毫秒 `TTFT`，以及其后的输出 token 每秒 `TPS`。非流式回复没有首 token，不更新。

排序用一次短回复的估计耗时：`TTFT + 200 * 1000 / TPS`。没报 `TPS` 的用本池已测席位的中位数，避免「没报速度」变成优势或惩罚。谁都没报，就只比首 token。

测过的按估计耗时从低到高画带，比本档最快慢过一成（`> 1.1 * top`）开新档。同一档按列出顺序，差几毫秒的通道不要每次请求对调。休息的在测过和没测过的后面，用尽的更后。

每 5 个「既有测过的、又有没测过的」请求，把一个没测过的轮到最前。不探测的话，慢过一次的席位再也不会被测到，变快了也回不来。探测在没测过的席位之间轮转，避免一个从不给速度的席位占住探测位。

## 平滑加权

权重 3 和 1 不应是「AAA 然后 B」，而要摊开：A, A, B, A, A, A, B, …。每个池记一张当前权重表。每一轮：没在休息的席位把自己的权重加进当前值，总权重是这些权重之和；当前值最大的当选，然后减去总权重。休息的不加，等于暂时让出份额，回来后按自己的权重重新加入。

会话粘性若把这一轮实际发给了另一个席位，调用 `MoveRound`：把刚扣掉的总权重加回抽中的那个，再从真正使用的那个扣掉。否则新对话会按「抽中但没用」去补份额，比例会漂。

## 免费快过期、最便宜

`expiring` 分三段。免费且未用尽的在最前：模型在该处不花钱（`Free`），或账号方案名像 free、trial、免费、试用（`FreePlan`）。这段按 `Expires` 排序，即窗口重置时间和积分作废时间里更早的那个，截断到小时。没填时间的排在后面。

付费且未用尽的接在后面，这段内部直接调用 Smart 的排序。用尽的在最后，和 Smart 的档 2 一样，还能花积分的在前。

`cheap` 只比价，不看额度。`Cost` 是此刻一百万输入加一百万输出的美元价，含用户倍率、费率窗口和厂商高峰。`CacheCost` 是一百万缓存读。没标价的排在所有有标价的后面。差不超过百万分之一，或不超过每百万 token 一美分，视为同价，避免舍入把两家对调。同价保持列出顺序。

## 照着实现时要守住的

1. `Apply` 对非法排列和 panic 退回列出顺序，不把请求打成 500。
2. Smart：周更早重置的在前；同一小时才比更小的窗口；`Unreached` 个最大窗口被跳过；截断到小时。
3. `Used == 0` 且没有任何重置时间的席位，在最少使用里排在「报过比例且还有空」的后面。
4. 速率和速度的分带先按数值排再画档，同一档保持原顺序。
5. 用尽再换：额度拒绝记入 `Drained` 后，即使窗口已重置，下一轮也不回到该席位。
6. 加权：粘性改派时用 `MoveRound` 改计数。权重 3 和 1 在 8 次请求里是 6 次和 2 次，并且不是连着把 3 次发完。
7. 速度优先：每 5 个混合请求有 1 个发给没测过的席位。
8. 策略内部不发请求、不等待。额度、价格、速度都由网关在调用 `Order` 之前填进 `Seat`。
