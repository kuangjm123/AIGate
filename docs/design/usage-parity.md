# 把用量模块补到接近 magpie

起点是 [用量](usage.md) 里那套账：`usage/attempts.jsonl`、按窗口合计、models.dev 的输入价和输出价、网关密钥的美元上限、DeepSeek 余额，以及 Codex / Claude / Gemini 的订阅额度。目标是这个仓库里已经在跑的用量模块（`internal/usage`、`internal/gui/usage.go`）。行为合同以 [用量账本](usage-ledger.md) 为准；本文只排实现顺序。

不要换存储，也不要重写已有的 `GET /usage`。旧行必须还能解析。新字段用 `omitempty`，缺了就当没有。记账失败仍然不能改变已经交给调用方的回复。

做完下面 1 到 5 步，另一个项目的用量页和密钥限额就和 magpie 的日常用法同一档。第 6 步是额度卡片，可以按厂商逐个加。第 7 步没有用户在页面上点，可以最后做。

## 1. 一次用户请求只算一次调用

现在每试一家就加一次 `calls`。magpie 不是这样。

同一次用户请求的每一行共用一个 `routeId`。已经向厂商拨号、并且产生了 token，然后失败并换下一家的那一行，加上 `handedOn: true`。没有 token 的失败不另写行。最后一行才是这次请求的结局；尝试多于一次时写上 `tries`。

合计改成：

- `handedOn` 不加 `calls`、不加失败次数。它的 token 和费用照加。
- 最终行算一次调用。HTTP 状态 ≥ 400，或有错误文案，且不是下面这种取消，算失败。
- 状态 499 且文案是 `the agent canceled the request` 算取消，不算失败，也不算成功。

探针、连通性检查、MCP、搜索如果也落行，加上 `source`，汇总前丢掉。不要把它们算进 `calls`。

验收：两行同一 `routeId`，第一行 `handedOn` 且有 token，第二行成功且 `tries: 2`。合计的调用次数是 1，token 是两行之和，失败次数是 0。

对应 magpie：`internal/gateway/gateway.go` 里失败且已计费的 `failedRow`，以及 `Totals.count`。

## 2. 读取时分组，并给出序列

保留现在的 `records` 和一份总 `summary`。在 `summary` 上增加：

- `agents`、`models`、`providerKeys`、`accounts`、`callerKeys`、`sessions`。每组有调用次数、五种 token、费用、无标价次数。
- `series`：`today` 按小时，`7d` 和 `30d` 按天，`all` 按周。每个点是该桶的合计。
- 请求列表分页：`offset`、`limit`，新的在前。筛选增加 agent、模型、调用方密钥 id。

会话组只包含写了会话标识的行。不要为没有会话标识的调用编一个 id。

供应商改名后，旧行仍写当时的 id。读取时按调用时间映到现在的 id 再分组。计价用改名之前的那家。映射放在内存里，不回写文件。

文件变长之后不要每次把所有行解析进一个切片。按 512 行分块，满块冻结；进程启动只解析上次块尾之后的新行。解析结果必须和逐行重读一致。

验收：同一模型两家供应商，分组里两行；0 点前的调用不进 `today` 的序列。

对应 magpie：`Summarize`、`internal/usage/log_index.go`。

## 3. 把价钱补全

目录价已经有输入和输出。读取时按这个顺序取价，仍然不写回文件：

1. 用户为 `供应商/模型`、`供应商/*`、或所有供应商下该模型写的价。写了 0 也算。
2. 目录里这家供应商的标价。供应商还不存在时，用模型厂商自己的标价。
3. 供应商倍率，或这一把上游密钥自己的倍率，乘在目录价上。用户写的价不再乘这层。
4. 调用时间落在高峰或费率窗口内时，再乘窗口系数。用行上的开始时间，不用「现在」。

费用公式：

```text
cost = (in * input
      + out * output
      + cacheRead * cacheRead
      + (cacheWrite - cacheWrite1h) * cacheWrite
      + cacheWrite1h * oneHour) / 1e6
```

`cacheWrite1h` 不能超过 `cacheWrite`。缓存单价缺了就不要把缓存 token 当成输入价来乘。有 token 但没有任何价，`unpriced` 加 1，费用不加。`in` 和 `out` 都是 0 的行不计费。

外部补报如果自带 `cost`，用那个数，不再乘标价。

验收：同一模型，高峰小时的一行费用是低谷的高峰系数倍。用户把价写成 0 之后，该模型的历史行费用变成 0，而不是退回目录价。

对应 magpie：`catalog.Price.CostSplit`、`Price.In`、`usage.Pricer`。

## 4. 密钥上限不止一条美元

现在是一个 `spendLimit` 加一个周期。改成一把网关密钥最多五条上限。每条可以卡 token，或卡美元，或两个都卡。0 表示这项不封顶。窗口用本地日历：今天、从周一起的一周、从 1 日起的一月，或从设定时刻起的若干小时、若干天。还可以只统计某些 `供应商/模型`。

拨号前把该密钥在每条上限的窗口里加总。美元用第 3 步的价。任何一条到顶就 429，不再拨号。价目或用量文件读不出来仍是 503，不要放行。

行上的 `callerKeyId` 继续用配置里的密钥 id，不是密钥原文。短时密钥再记 `callerIssuerId`，同一笔花费同时算进签发它的那把密钥。`handedOn` 的 token 和费用占上限。`source` 为补报、探针、MCP、搜索的行不占。取消不占。

页面上「清除」只是记下「这个供应商的这个模型，这个时刻之前不再显示」。文件不删。密钥上限仍然数这些行。

验收：日上限已满、周上限未满时拒绝。短时密钥花掉的钱出现在签发密钥的已用额里。清除之后页面合计变小，上限判断不变。

对应 magpie：`access.Limit`、`budget.Append`。

## 5. 页面上多出来的四种读法

合计和分组做完再加，它们都读同一份过滤结果：

| 读法 | 行为 |
| --- | --- |
| 热力图 | 最近 53 周，每天一格，用当前筛选 |
| CSV | 与当前列表同一批行，含 token、费用、状态、会话、密钥 id。费用是读取时算的 |
| 当前流量 | 这一刻的上下行字节和正在进行的请求，不读历史文件 |
| 打开一行 | 用会话标识读本进程自己的会话归档，取这段时间的原文；不打开 agent 自己的会话文件。用量文件里仍然不存正文 |

会话归档按 session 存，不按 agent 再分一层；这是本仓库已接受的差异。存不了盘或某一整行解析不了时，页面保持现在的「不可读」，不要返回半份合计。

对应 magpie：`GET /api/usage/heatmap`、`/api/usage/requests.csv`、`/api/usage/traffic`、`/api/usage/requests/content`。

## 6. 余额和额度按卡片加，不要绑死 DeepSeek

余额仍是当场问厂商，不从账本减。把「只有 DeepSeek」改成一张表：主机名到 URL 和响应里的金额字段。一家有多把开着的密钥、又没有共用的账户 token 时，每把各问一次。问过的结果留一分钟。厂商失败时卡片保留上一次的数，并标上错误。没有接口的主机可以手填余额，或让用户填一个余额 URL。不要对 OpenAI、Anthropic、Gemini 的普通 API 密钥发明余额接口。

订阅额度保持现在的三条路：Codex 用登录态问 `/wham/usage`，Claude 跑本机 `claude -p /usage`，Gemini 用登录态读 `quotaInfo`。密钥买来的套餐窗口单独成一类，不要和「还剩多少钱」混在同一张卡的同一个字段里。

每加一家，用它的一份真实响应做测试。问失败不得改账本。

对应 magpie：`provider.KeyBalances`、`balanceSourceOf`、`provider.Quotas`。

## 7. 最后再做的三件

这三件不影响页面上的合计，可以等 1 到 5 步稳定：

- `POST` 补报直连厂商的调用。这些行进合计，不占密钥上限，路由和会话归并不读它们。同一请求 id 不写第二次。
- 行上增加首 token 毫秒、生成耗时、排队和重试毫秒、上下行字节。路由用的速度仍是内存里的衰减平均，不要改成回放这个文件。
- 用量文件与配置分开同步；需要时再按 OTLP 导出。导出的是元数据，不是提示词。

## 不要做的

- 不要为了像 magpie 而改路由。策略 `usage` 继续用内存里的使用量，不读这本账。
- 不要把提示词和回复写进用量行。
- 不要在第一轮实现每家签到、额度历史曲线、远程 magpie 的额度卡。那些是第 6 步之后的增量。
- 不要把旧行迁移成新文件。缺字段的旧行按 [用量](usage.md) 现在的规则解析。

## 做到哪算接近

1 到 4 步的验收都过，并且热力图、CSV、清除后的页面与限额不一致这三件事和上面写的一样，就可以把这个用量模块当成 magpie 的同一档。余额表里有 DeepSeek 以外的至少一家，以及手填余额，额度卡片就和 magpie 的日常显示同一类。
