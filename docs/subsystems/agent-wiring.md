# Agent wiring

The console Agent page detects coding agents on this computer. Connecting one writes that agent's own config so its model calls go to this gateway, and records the values it replaced. Disconnecting writes those recorded values back. Other fields in the same file are left as they are, including fields the user edits after connecting.

The notes of a connection are not in the config document. They are `agents/<id>.json` in the directory that contains the config file. A failed read of that note, or of the agent file, is `unknown`. Connect and disconnect then write nothing. A missing note is not a connection: disconnect does not guess the previous config.

A second connect keeps the first note. Reconnect rewrites the gateway values and does not replace the saved previous values. If the agent file no longer matches what connect wrote, or a saved URL is for a different gateway origin than the one listening now, the state is `drift`.

The value written as the key is `aigate-<id>`. It is the local caller name, not an upstream provider key. On a loopback peer it is accepted and stored as the caller. A remote peer, or a request with `X-Forwarded-For` or `Forwarded`, is `auth_failure` unless the credential is an issued gateway token. `magpie` and `magpie-<name>` are still caller names.

Connect refuses, and writes nothing, when the gateway is not listening (`not_listening`), when there is no conversation model to offer (`no_models`), when the agent is not installed (`absent`), or when the file is not one this process can edit without dropping other values (`unknown`). A hidden, image, or video model is not offered. A route name is offered as itself when it is one non-empty model name with no leading or trailing whitespace and no comma. A group is offered as `group/<id>`. A provider model is offered as `providerId/model`. A subscription model is offered as `login/<account>/<model>` from [accounts](accounts.md). The sign-in itself is not copied into the agent config.

Cursor is detected and not edited. Its state is `manual`.

How a plugin is loaded, and which further agents get a migration, stay open. See [gateway design](../design/gateway.md).

## Codex

Codex is wired as an explicit gateway provider rather than beside a ChatGPT sign-in. The first connect records the top-level `model`, `model_reasoning_effort`, `model_provider`, `model_catalog_json`, and `openai_base_url` as it finds them, plus whether `aigate-models.json` existed and its bytes. Connect does not write `model_reasoning_effort`: the key stays as the user set it and is read for the catalog's default. A later connect rewrites the gateway values without replacing the recorded originals.

The written top level is:

- `model_provider = "aigate"`.
- `model` is the selected catalog id: a route, `providerId/model`, `group/<id>`, or `login/<account>/<model>`.
- `model_catalog_json` names `aigate-models.json` beside `config.toml`. On Windows the value is the bare filename so a config read through WSL still resolves it. On macOS and Linux it is an absolute path.
- `openai_base_url` is the gateway origin plus `/backend-api/codex`. It is written only when the key was empty or already held AIGate's address. A user-written address of another origin is left alone. A user's own line for AIGate's address is recorded, so disconnect can put that line back rather than remove a key it found.

The table `[model_providers.aigate]` has `name = "AIGate"`, `base_url` (origin plus `/v1`), `wire_api = "responses"`, `experimental_bearer_token`, and `http_headers` with `x-openai-actor-authorization = "aigate"`. When a connect has to write a token for a loopback origin, it writes the local caller name `aigate-codex`; an existing non-empty token there stays. An origin away from loopback needs a token the gateway issued: connect writes the first live gateway token the console listed, and refuses `no_credential` without writing when there is none. An existing token is kept when it is that token or another key the gateway accepts. When that written token has a model list, the generated catalog and the model connect chooses are limited to the same ids. A token that leaves no offered model is refused as `no_models` before anything is written. The gateway applies the same list to a remote Codex at `GET /v1/codex/models`.

Other headers, unknown provider fields, and comments are kept. If the headers are already a `[model_providers.aigate.http_headers]` table, an inline table, or dotted keys, the actor header is written into that form instead of adding a second definition.

No-login wiring does not write `requires_openai_auth`, so Codex's app-server reports no account while requests still use the gateway token. A user-written `requires_openai_auth = false` stays. An old `true` is removed because it cannot keep a ChatGPT account here.

`aigate-models.json` is the Codex `models.json` shape rendered by [codexcat](../../internal/codexcat/codexcat.go): each offered model has `slug`, display name, instructions, reasoning levels, window, compaction threshold, and tool fields. The levels come from provider `ModelInfo`, a group's `levels`, or readable subscription metadata; a known empty list gives no selector level. A non-OpenAI reasoning model also offers `ultra`, which the gateway fits to `max` before an upstream request. It does not claim `supports_search_tool`, because AIGate does not turn Codex's tool search into a gateway call. The configured `model_reasoning_effort` is the entry's default level when the model reasons; otherwise the model default is used. Keys a user adds at the top level or to an entry are kept on the next connect. Models Codex used most recently are ranked into the first 100 entries the desktop app reads. AIGate does not write `models_cache.json` or a desktop-only catalog file. The complete mapping is [reasoning](reasoning.md).

Codex sends the actor header on its model calls. The gateway records those calls as agent `codex` even though the bearer is the `aigate-codex` caller name, so the catalog's recent-model order follows them. Status is `drift` when the saved values no longer match, the `model_catalog_json` key is empty, the file it names is missing, the actor header is not `aigate`, or the recorded credential is no longer one this gateway accepts; reconnecting writes the gateway values, catalog, and header back. The Agent list's refresh first runs the same repair: a missing `aigate-models.json` is written again while `model_provider` is still `aigate`, and a `model_catalog_json` that names that generated file is removed once the user moved Codex to another provider. An unreadable note or config is left alone.

If Codex already enabled background compaction, the provider table also receives `capabilities = { remote_compaction = "v2" }` unless the user already supplied any capabilities. The on forms read are a bare `async_compaction = true` under `[features]`, an inline or dotted `features.async_compaction` key, and `enabled = true` in `[features.async_compaction]`. AIGate does not ask Codex's version, turn the feature on, write a `[features]` key, or write a `[features.async_compaction]` table of its own.

The connection note records whether AIGate wrote the capability. A later connect or disconnect removes it only when the feature is now off and the value is still exactly AIGate's inline `{ remote_compaction = "v2" }` with no other capability. A capability the user changed stays.

Disconnect restores the recorded `model`, `model_provider`, and `model_catalog_json`. It restores `openai_base_url` only while that key still holds the address connect wrote: the recorded line goes back, or the key is removed when it was not there before. A line the user changed after connecting stays. It restores the recorded `model_reasoning_effort` only when the file has none; a value the user set or changed after connecting stays. It does not remove `[model_providers.aigate]`: threads started on that provider cannot load without it.

On an interrupt, hangup, or SIGTERM, the process runs the same Codex disconnect before it stops the listeners. A Codex with no connection note, or one no longer detected, is left alone. An unreadable note or config is left as it is and logged, and the process still exits.

An `aigate-models.json` that was already there when connect first wrote the file is put back byte for byte when the file still holds exactly the generated catalog with that original file's extra keys carried over. One the user changed after connecting stays as changed. One created by this connection is removed only while its bytes are still exactly what connect generated. The connection note keeps a fingerprint of a remote bearer token, not another plaintext copy, and records whether AIGate wrote the compaction capability.

Another machine's Codex does not read this file. It asks the gateway's `GET /v1/codex/models` with a gateway token; the reply uses the same entry shape, keeps only models that token allows, and puts that token's recently used models into its first 100.

## Claude Code

Claude Code's settings file is `$CLAUDE_CONFIG_DIR/settings.json` when `CLAUDE_CONFIG_DIR` is set, otherwise `~/.claude/settings.json`. The same directory is used to detect the agent, read its sign-in, and start the `claude` process for a subscription call. When the variable is set, `~/.claude` is not read.

Connect writes these fields into the user's settings file:

- `env.ANTHROPIC_BASE_URL` is the gateway origin.
- `env.ANTHROPIC_AUTH_TOKEN` is `aigate-claude`, sent as `Authorization: Bearer`.
- `env.ANTHROPIC_API_KEY` is `""`, so a real Anthropic key is not sent as a second credential.
- `env.CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` is `1`.
- `model` is the offered main model. An offered model whose context is at least 1,000,000 gets a `[1m]` suffix; an id that already ends in `[1m]` is left as it is.
- `env.ANTHROPIC_DEFAULT_OPUS_MODEL`, `env.ANTHROPIC_DEFAULT_SONNET_MODEL`, `env.ANTHROPIC_DEFAULT_HAIKU_MODEL`, and `env.ANTHROPIC_DEFAULT_FABLE_MODEL` are chosen from offered models whose id, bare id, or display name contains that tier. A tier with no matching model uses the main model.
- `env.ANTHROPIC_SMALL_FAST_MODEL` is the `haiku` value, and `env.CLAUDE_CODE_SUBAGENT_MODEL` is the main model.
- `env.CLAUDE_CODE_USE_BEDROCK`, `env.CLAUDE_CODE_USE_VERTEX`, `env.CLAUDE_CODE_USE_FOUNDRY`, `env.CLAUDE_CODE_USE_ANTHROPIC_AWS`, `env.CLAUDE_CODE_USE_ANTHROPIC_GOOGLE_CLOUD`, and `env.CLAUDE_CODE_USE_MANTLE` are `""`. An empty value in this file overrides a shell value, so these paths do not bypass the gateway.
- `env.ANTHROPIC_MODEL` is removed. Claude Code gives that key priority over `model` and `/model`; keeping it would pin the model on every start.
- `modelPicker.options` lists each offered conversation model with `description` `via AIGate`. A model id that Claude Code's own discovery would filter out, such as `deepseek-v4-pro`, can still be chosen from `/model`. A route enters this list only when its `modelMatch` is one non-empty model name with no leading or trailing whitespace and no comma. User options stay; an earlier AIGate list is refreshed on reconnect.

Connect records whether each field existed and its previous string value. An older note that lacks one of these fields takes the missing previous value from the current file on the next connect. Disconnect puts each field back only while its current value still equals what connect wrote. A value the user changed stays, including a later non-empty `ANTHROPIC_MODEL`, cloud switch, or edited `modelPicker`. A field connect wrote as `""` restores its previous value only when the field is absent, empty, or still `""`. The top-level `model` follows the same rule. A `modelPicker` that connect first created is removed while its JSON is still exactly the generated value; one that existed before is restored.

Status is `drift` when a recorded gateway field no longer matches, when a managed empty value is absent, when `modelPicker` changed, or when `ANTHROPIC_MODEL` is present again while the rest still matches. A top-level tier name (`opus`, `sonnet`, `haiku`, or `fable`) is not drift when that tier's recorded gateway model still matches what connect wrote; Claude Code's `/model` saves the alias rather than the id. A concrete model that `/model` picked from the AIGate list is not drift either, because Claude Code changes only the top-level `model`. It is `on` only when every managed field still matches and `ANTHROPIC_MODEL` is absent.

Claude Code always sends Anthropic Messages. A provider with an empty protocol receives that same body, so the upstream must itself speak Anthropic. An OpenAI-compatible upstream such as DeepSeek needs `protocol` set to `chat` on that provider, or a route or group member that uses such a provider; otherwise the upstream can answer 404 at `/v1/messages`, and Claude Code reports the selected model as missing or inaccessible. AIGate does not rewrite an empty protocol, because it is also the correct setting for an Anthropic-compatible upstream.

Claude Code's own gateway model discovery keeps only ids containing `claude` or `anthropic`. Connect's `modelPicker.options` is the explicit list that lets a configured id such as `deepseek-flash` or `deepseek-v4-pro` appear in `/model` anyway. The id must resolve to a route, group, or provider model in the gateway catalog.

A cloud switch or `ANTHROPIC_BASE_URL` from managed settings, the shell, or `~/.claude.json` is outside this file. A managed value can still take precedence; AIGate does not edit those layers.

A JSON file that is not one JSON object is `unknown`. Connecting a JSON file rewrites that file with the same values plus the fields above. A file this process created, and that disconnect leaves empty, is removed.

## API

`GET /agents` returns every agent above. `POST /agents/{id}/connect` and `POST /agents/{id}/disconnect` do the write. The response does not include a credential that was in the file before. The caller-facing codes are on the [console](console.md) page.
