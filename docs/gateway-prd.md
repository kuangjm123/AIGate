# AI 网关产品需求

本文描述本机 AI 网关对使用者和接入应用承诺的行为。它按现在已经提供的能力来写，供对照实现和迁移到别的项目时使用。请求从应用到模型再回来的路径见 [网关链路](gateway-chain.md)。函数名和实现不在这里。

## 问题

使用者在同一台电脑上同时开着多个编程助手。每个助手只认自己的协议、自己的密钥和自己的模型菜单。模型则来自多家 API 和多种订阅，地址、额度和失败方式各不相同。

没有网关时，使用者要在每个应用里重复填写供应商，一个账号用尽或报错时对话就停在那个应用里，用量也散落在各处。

## 产品目标

网关是本机上的一个 HTTP 服务。应用只对接这一个地址。网关负责：

- 用应用自己的协议接收对话，再翻译成真正提供模型的那一家能接受的协议，并把回复翻回去。
- 按使用者配置的供应商、订阅账号和路由组，决定这一次发给谁；这一家暂时不能接时，在还没有把回复交给应用之前换下一家。
- 把每次调用记到同一本用量账上，并能归到同一段对话。

成功时，应用不需要知道最终是哪家密钥或哪个订阅账号答的。失败时，应用收到它自己的协议里的错误，并能从路由记录里看出试过谁。

## 使用者

| 谁 | 要完成的事 |
| --- | --- |
| 本机使用者 | 添加供应商和订阅，把应用接到网关，在一个界面里看用量、配额和这次为什么选了某一家 |
| 本机上的编程助手 | 用自己的协议发对话、列模型、带上会话标识，不必为每一家供应商各写一套 |
| 局域网或另一台电脑上的客户端 | 持有单独发放的网关密钥，访问同一网关 |
| 插件作者 | 在选路前补充上下文，或在请求和回复上改写、拒绝、跳过某个账号，而不改应用 |

## 范围

### 包含

- 本机网关进程：随桌面程序一起开，或只开网关、不打开窗口。
- 对话协议：Chat Completions、Responses、Anthropic Messages、Gemini、Ollama。
- 模型目录：API 密钥供应商、订阅账号、路由组，以及发给应用的模型列表。
- 选路：尝试顺序、同一段对话尽量留在同一家、暂停、备用、失败后换下一家。
- 协议翻译：流式输出、工具调用、图片和推理相关字段，在双方协议之间转换。
- 用量、配额、路由记录、会话归并。
- 两类扩展：选路前可补充上下文的异步钩子；可改写或拒绝请求、可跳过账号、可改回复事件的请求中间件。
- 发给应用的附加工具：搜索、识图、记忆。这些工具再向网关要模型。

### 不包含

- 替应用执行工具，或替应用进行下一轮推理。一次客户端请求对应一次模型调用。工具声明、工具执行和随后的推理轮次属于客户端。
- 读取应用厂商自己的私有模型列表。应用菜单里的模型来自网关目录。
- 在网关里保存第二份应用配置。接入改的是应用自己的文件；断开时把应用原来的配置放回去。
- 用提示词、密钥或网络地址猜测一段对话属于谁。会话以客户端带来的标识为准。没有标识的请求不编造会话，也不记录正文。个别应用新版本不再带标识时，只用它本机上自己写下的会话文件来对上。

## 场景

1. 使用者添加一个 API 供应商或登录一个订阅，再把 Codex、Claude Code 或 WorkBuddy 接上。应用的基地址、密钥和模型列表被写成网关的。使用者在应用里选一个模型并发起对话，回复来自网关背后的那一家。
2. 使用者把多家放进同一个路由组。应用只看到这一个名字。一段对话里的请求尽量发给同一家，以便上下文缓存还在。这一家报错或额度用尽、并且回复还没开始交给应用时，网关换组里的下一家。
3. 另一台电脑持有网关密钥，把请求发到这台机器打开共享之后的地址。用量记在这把密钥上。这把密钥若被限制了模型、账号或预算，只能看到和使用被允许的部分。
4. 插件在请求发出前补上一段上下文，或在某一家供应商上改写正文。应用仍按自己的协议收发。插件失败时，对话继续用改写之前的正文。

## 功能需求

### 进程与地址

1. 网关默认听在 `127.0.0.1:3425`。使用者改过端口时，以设置里的地址为准。
2. 打开桌面程序，或单独启动网关服务，都会把这个地址占上。端口已被占用时，后启动的不再占第二个，已有的网关继续服务。
3. 本机客户端用 `GET /api/hello` 确认对方是这个网关。应用发现这里没有网关时，应继续使用它自己的供应商。

### 接入应用

4. 接入修改的是应用自己的配置：基地址指向网关，密钥写成网关发给该应用的密钥（`magpie` 或 `magpie-<应用名>`），模型列表写成网关当前目录。
5. 没有可用模型，或模型都被隐藏时，接入失败并说明原因，不写入一份空列表。
6. 断开接入时，只收回网关写进去的值，并把接入前的配置放回去。使用者后来自己改过的值保留。
7. 只在启动时读模型列表的应用，接入之后需要重新打开，菜单才会更新。
8. 网关在本机接受任意密钥。密钥写成 `magpie-<应用名>` 时，用量、请求记录和按应用匹配的路由规则都记在这个名字下。未带这把密钥时，按客户端标识的第一个词归类。
9. 来自另一台电脑的请求必须带有使用者发放的网关密钥。本机应用使用的密钥，和发给别人的密钥，对插件来说是不同来源。

### 协议入口

10. 应用按自己的协议发送，网关按路径识别：

    | 协议 | 路径 |
    | --- | --- |
    | Chat Completions | `POST /v1/chat/completions` |
    | Responses | `POST /v1/responses` |
    | Anthropic Messages | `POST /v1/messages` |
    | Gemini | `POST /v1beta/models/{模型}:{方法}` |
    | Ollama | `POST /api/chat` |

    OpenAI 客户端的基地址带到 `/v1`。Anthropic 和 Gemini 的基地址带到网关根路径。
11. 供应商本身就说同一种协议时，请求按原样转发。否则翻译成对方的协议。流式输出保持流式。工具调用、图片和推理相关字段一起转换。
12. 模型不接受图片或视频，而这次请求带了当前要看的图片或视频时，拒绝这次请求并说明原因，不把媒体悄悄丢掉后只把文字发给模型。
13. 标题、摘要、压缩这类附属请求由网关单独处理，不占用这段对话的主选路。
14. 错误按应用自己的协议返回。

### 模型目录

15. `GET /v1/models` 列出使用者当前打开的对话模型。每条至少包含标识、显示名和所属供应商。已知时还包含上下文窗口、推理档位、是否接受图片。
16. 模型标识是 `供应商/模型`，或路由组的名字。应用把列表里的标识原样发回。
17. 默认列表只有对话模型。图片和视频模型需另行请求，并标出种类；它们走图像或视频接口，不走对话接口。
18. 应用应从这份列表读取模型，而不是在应用里写死一份。使用者在网关里增删供应商后，列表跟着变。
19. 隐藏或停用的模型不出现在列表中，也不能被调用。

### 选路

20. 模型名解析为一个供应商，或一个路由组。路由组把多家密钥或账号放在同一个名字下。
21. 候选顺序由路由策略、会话亲和、暂停规则和备用列表共同决定。同一段对话可以固定在上一次用的那一家。
22. 主选暂时不能接，并且回复还没有开始交给应用时，按候选继续尝试。已经开始回复之后不再换人。
23. 候选都不可用时，请求失败。原因是此前某一次真实失败，或没有任何一家就绪。读配置失败视为未知，不视为空名单从而放行。
24. 使用者为密钥或账号设置的额度、速率和暂停生效。全部剩余候选都在休息或都要等到厂商给出的时间时，立即告诉应用，不再空等。
25. 网关自己发起的请求（标题、选路用的分类、替模型做的搜索或识图）直接选路，不经过应用请求上的钩子和中间件。

### 扩展

26. 异步钩子在选定供应商之前看到应用自己的协议正文，可以补充上下文。模型名、是否流式、工具声明保持不变。它不能拒绝请求。失败、超时或改了不许改的字段时，使用上一份被接受的正文，请求继续。
27. 回复交给应用之后，钩子可以观察这份回复，但不能改写应用已经收到的内容。通知不挡住应用收完。请求失败、流中途断开，或回复大到无法整份保留时，钩子被告知没有完整回复。
28. 请求中间件在选路前可以改正文，也可以拒绝。拒绝时应用收到它自己的协议里的错误。
29. 每一次尝试发送前，中间件可以只改发往这一家的正文，也可以跳过某个订阅账号。对这一家的修改不带到下一家。跳过的账号不休息、不记为失败。密钥的尝试不能被按账号跳过。
30. 中间件可以改流式事件和整份 JSON 回复。中间件抛错、超时或返回无法使用的结果时，这一处保持原样，请求继续。
31. 两类扩展都只作用在应用发来的请求上。未启用时，请求按原样选路。

### 用量、配额与会话

32. 每次调用记下：调用方、请求的模型、实际服务的供应商和账号或密钥、耗时、是否失败、用量。路由记录能看出选了谁、换过谁、为什么。
33. 应用用会话头标出同一段对话时，这些调用归到这个标识下。网关把该标识回给客户端。没有标识的请求不编造会话，不记录正文。
34. 会话页同时看应用自己写在磁盘上的会话和网关用量。同一段对话两边都有时，以应用自己的会话为准，用量不重复计算。
35. 本机可以查询订阅配额、用量汇总和单次请求。另一台电脑持有网关密钥时也可以查询，但只能看到这把密钥被允许看到的范围。被限制预算、模型或账号的密钥看不到全部配额，除非使用者明确打开。
36. 应用可以把自己直接发给厂商的调用补记进同一本账。补记的记录出现在用量里，不占用网关密钥的额度。

## 非功能需求

1. 默认只听本机回环地址。对局域网或其他机器提供服务时，必须由使用者打开共享，并使用单独发放的网关密钥。
2. 转发来的流量即使管理员信任那台代理，来源仍视为远程，不把它当成使用者本机上的应用。
3. 钩子看不到请求头和客户端密钥，也不能从网关得到对方的网络地址。跳过账号时使用的账号引用不能还原出邮箱。
4. 读配置、解析或校验失败表示未知。它不表示空、没有或不需要更换。保护访问的名单在文件读不出时拒绝访问。
5. 网关的默认值不覆盖使用者已经设置的值。
6. 应用侧的流式回复边收到边转发。钩子对完整回复的观察发生在应用已经开始接收之后，不增加应用收尾的等待。
7. 同一端口只由一个网关进程服务。

## 验收

- 应用只配置网关地址和一把 `magpie-<应用名>` 密钥，就能用目录里的模型完成一次对话，并在用量里记到这个应用名下。
- 目录中的模型增删或隐藏之后，模型列表和拒绝规则一起变化。隐藏的模型不能调用。
- 路由组的第一家在回复开始前失败时，应用仍能从下一家得到回复；路由记录写明换过谁。第一家已经开始回复之后失败，不再静默换人。
- 供应商协议与应用协议不同时，流式文本、工具调用和推理字段仍按应用原来的协议返回。
- 断开接入后，应用配置回到接入前，使用者后来改过的项还在。
- 未打开共享时，另一台电脑不能调用。打开后，没有网关密钥的请求被拒绝。
- 关闭钩子和中间件后，同样的对话仍能选路并返回。钩子失败时对话继续。中间件拒绝时，应用收到它自己的协议里的错误。
